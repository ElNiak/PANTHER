$ ai-rfc checkpoint --help
usage: ai-rfc checkpoint [-h] [--consolidation CONSOLIDATION] [--base BASE] cluster_id

Freeze the manifest against one cluster. Checkpoints are write-once: what a revision cited stays
readable after the manifest moves on.

positional arguments:
  cluster_id            Cluster to freeze against; checkpoints are write-once.

options:
  -h, --help            show this help message and exit
  --consolidation CONSOLIDATION
                        Write consolidation NN under consolidations/ instead of a cluster
                        checkpoint.
  --base BASE           The cluster checkpoint the consolidation follows, workspace-relative;
                        required with --consolidation.

$ ai-rfc claim upsert --help
usage: ai-rfc claim upsert [-h] [--text TEXT] [--section SECTION] [--level LEVEL] [--layer LAYER]
                           [--field FIELD] [--anchor ANCHOR]
                           claim_id

positional arguments:
  claim_id           Claim id, e.g. 'mark:alg.1'.

options:
  -h, --help         show this help message and exit
  --text TEXT        The requirement, as one normative sentence.
  --section SECTION  Draft section number, e.g. '3.1'.
  --level LEVEL      RFC 2119 keyword: MUST, SHOULD or MAY.
  --layer LAYER      Architectural layer the claim belongs to.
  --field FIELD      Extra field as key=value (req_class, intent, question-id, testable).
  --anchor ANCHOR    Anchor as JSON, e.g. '{"evidence_class": "code", "locator": "src/a.py",
                     "commit": "<sha>", "line": 42}' or a decision record, '{"evidence_class":
                     "adr", "locator": "<sha>"}'; repeatable, replaces the claim's anchors when
                     given.
