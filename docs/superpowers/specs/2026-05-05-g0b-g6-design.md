### 2. G0b dispatch flow (PostToolUse via the parametric dispatcher)

```
User issues Edit/Write/Bash/NotebookEdit (after plan_approved)
  │
  ├─ Tool runs first (file written / command executed)
  │
  ├─ PostToolUse: run-gate.py --id g0b   [routes via GATES["g0b"] in registry.py]
  │   ├─ tool_name in watched_tools? (Edit/Write/Bash/NotebookEdit) — else emit_noop and return
  │   ├─ parse_g0b(hook_input) → ctx = {tool_name, artifact (file_path or command), tool_input_digest, tool_result_excerpt}
  │   ├─ predicate_g0b(ctx):                                            # per F-C1, F-C2, F-C3
  │   │   ├─ Read journal: get_journal_entries(ctx["protocol_dir"], last_n=20)
  │   │   ├─ Find most recent plan_approved at ts=T0. None? → return False.
  │   │   ├─ Find most recent gate_dispatched{gate=g0b} at ts=T_d (None if absent).
  │   │   ├─ Find most recent gate_verdict{gate=g0b}    at ts=T_v (None if absent).
  │   │   ├─ Pairing (F-C3):
  │   │   │   - If T_v exists and T_v > T0  → cycle closed → return False (already paired)
  │   │   │   - If T_d exists and T_d > T0:
  │   │   │       · If T_v ≥ T_d            → cycle closed → return False
  │   │   │       · Elif (now - T_d) ≤ 2h   → cycle in flight → return False (no double-fire)
  │   │   │       · Else                    → orphan dispatch → return True (re-fire G0b)
  │   │   │   - Else                        → return True (no dispatch yet for this plan_approved)
  │   │   └─ No plan-mode check (F-C2): plan_approved is only emitted on plan-mode exit, so plan-mode naturally returns False above when no plan_approved is in the window.
  │   ├─ dispatch_g0b(ctx):
  │   │   ├─ append_journal_event("gate_dispatched", {
  │   │   │     "gate": "g0b",
  │   │   │     "trigger": "run-gate.py --id g0b",
  │   │   │     "artifact": ctx["artifact"],
  │   │   │     "tool_name": ctx["tool_name"],
  │   │   │     "plan_approved_ts": T0,                                  # ISO; per F-C1
  │   │   │   }, workflow=<active>, phase=<active>)
  │   │   └─ emit_hook_output(
  │   │         "PostToolUse",
  │   │         system_message=f"[G0b plan-fidelity gate] dispatched on {basename(artifact)}; gate_dispatched appended to journal at {journal_path(...)}",
  │   │         additional_context=(
  │   │             "[G0b plan-fidelity gate] First action after plan_approved completed. "
  │   │             "Dispatch g-fidelity-critic ×3 in parallel per skills/ivy/references/parallel-dispatch.md "
  │   │             "to verify this action conforms to the plan's first task.\n\n"
  │   │             f"Action observed: {tool_name} on `{artifact}` "
  │   │             f"(tool_result excerpt: {tool_result_excerpt[:200]}).\n"
  │   │             f"Plan reference: plan_approved at ts={T0}.\n\n"
  │   │             "Each critic loads g-fidelity-critic.md and applies the per-task plan-conformance rubric. "
  │   │             "Aggregate via 2-of-3 asymmetric vote. "
  │   │             "On UNSOUND, follow the gate-verdicts.md G0b section routing (revert / override / return-to-plan-mode)."
  │   │         ),
  │   │     )
  │
  └─ Claude reads tool result + additionalContext
      ├─ Single-message dispatch: Agent(g-fidelity-critic) ×3 with verbatim prompt + ctx
      ├─ Aggregate per skills/ivy/references/parallel-dispatch.md asymmetric vote:
      │   - ≥2 SOUND      → write gate_verdict{gate=g0b, verdict=SOUND}; emit pending_dispatch(<caller>, reason="post-G0b-SOUND"); proceed
      │   - ≥2 UNSOUND    → write gate_verdict{gate=g0b, verdict=UNSOUND, drift=<str>, plan_task=<ref>}; halt next actions; surface DR-14 routing prompt
      │   - ≥2 ABSTAIN    → write gate_verdict{gate=g0b, verdict=ABSTAIN}; re-dispatch ×3 with refined input; cap at 2 cycles → halt
      │   - Mixed (1-1-1) → ABSTAIN
      └─ Verdict written before user-visible response (closes the cycle for predicate_g0b's pairing rule)
```

Three correctness anchors versus the earlier PreToolUse-advisory shape:
- The critic receives the actual `tool_result` excerpt (≤200 chars) inline — it compares what was *actually* written against the plan's first task without first re-reading the file. Read/Grep spot-checks remain available for deeper inspection but are no longer required for correctness.
- The pairing rule above closes the ~90s race window where two qualifying tool calls between `gate_dispatched` and `gate_verdict` would otherwise double-fire G0b (per F-C3).
- The 2h staleness fallback keeps G0b functional when a hook crash leaves an orphan `gate_dispatched` (mirrors the existing `is_workflow_stale` convention in `workflow_state.py`).

### 3. G6 dispatch flow (Phase 1.5 detection + inline + opt-out)

```
Session N+1 starts → orchestrator turn 1 (skills/ivy/SKILL.md Phase 1.5)
  │
  ├─ If plan-mode active → SKIP entire Phase 1.5 (per existing skip clause)
  │
  ├─ Existing: consume fresh pending_dispatch (<2h) → workflow_resumed → set_active_workflow → dispatch
  │
  ├─ Existing: PROJECT.md warm-resume (Resume / Switch / Idle) — fires when PROJECT.md mode is non-idle
  │
  ├─ NEW G6 detection branch (only if NEITHER warm-resume branch fired — i.e., this is a cold-start-eligible turn):
  │   # F8 ordering rationale: "workflow-resume turns prioritize the resumed workflow over knowledge capture";
  │   # both pending_dispatch warm-resume AND PROJECT.md warm-resume count as workflow-resumes for this purpose.
  │   # Per F-W1, G6 sits AFTER PROJECT.md so PROJECT.md resume never pays the ~90s G6 cost.
  │   ├─ Read journal: get_journal_entries(ctx.protocol_dir, last_n=200)  # wider window for session_end pairing
  │   ├─ Find most recent session_end at ts=T_s. None? → skip
  │   ├─ Find most recent gate_verdict{gate=g6} at ts=T_v6 (None if absent).
  │   │   Pair (per F-C1, F-C3): "unpaired" iff T_v6 ≤ T_s OR T_v6 is None.
  │   ├─ If paired → skip (G6 already ran for this session)
  │   ├─ Read env: IVY_DISPATCH_G6 (default "1"). If "0" → emit [ivy-noop] G6 skipped (env opt-out); skip
  │   ├─ Note: G6 dispatch is gated indirectly by is_session_active() per record/session-end.py:25 —
  │   │       sessions without Ivy activity skip session_end entirely, so G6 never fires for them. By design (F6).
  │   ├─ Candidate writer:
  │   │   ├─ Extract candidates from events between the prior session_start (ts=T_start) and T_s
  │   │   ├─ Source event_types: progress{kind=fix_attempt}, decision, error, unsound gate_verdict
  │   │   ├─ Build {candidate_id, source_event_type, source_event_ts, summary≤200, evidence_paths}
  │   │   │   (source_event_ts replaces source_event_index per F-C1)
  │   │   ├─ Pre-filter: drop candidates whose candidate_id already appears in any prior knowledge_captured
  │   │   └─ If batch empty after pre-filter → emit [ivy-noop] G6: no fresh candidates; skip
  │   ├─ append_journal_event("gate_dispatched", {"gate": "g6", "candidate_count": N, "session_end_ts": T_s})
  │   ├─ Dispatch g-knowledge-critic ×3 in parallel (single message, three Agent calls); ~90s blocking
  │   ├─ Aggregate batch verdict per skills/ivy/references/parallel-dispatch.md
  │   ├─ append_journal_event("gate_verdict", {"gate": "g6", "verdict": <SOUND|UNSOUND|ABSTAIN>, "candidate_count": N})
  │   └─ Per-candidate aggregation:
  │       - ≥2 KEEP   → append knowledge_captured(candidate_id, summary, evidence_paths, confidence="high")
  │       - ≥2 DROP   → no journal write
  │       - ≥2 DEFER  → AskUserQuestion(KEEP / DROP / SKIP):
  │                       KEEP → append knowledge_captured(..., confidence="user-confirmed")
  │                       DROP → no journal write
  │                       SKIP → no journal write; candidate NOT added to dedup set (eligible for re-vote next session)
  │       - 1-1-1     → DEFER (then AskUserQuestion as above)
  │
  └─ Existing: cold start (Scaffold / Refine / Experiment) — fallback when neither warm-resume nor G6 fired
```

### 4. DR-14 closure draft — gate-verdicts.md G0b row

(Prose ready to paste into `panther-ivy-plugin/.claude/rules/gate-verdicts.md` after the existing G0 row.)

```markdown
### G0b — plan-fidelity (per-action)

| Verdict | Meaning | Routing |
|---|---|---|
| SOUND | Action conforms to first task of approved plan. | Emit `pending_dispatch(<caller>, reason="post-G0b-SOUND")` and proceed. Subsequent actions in the same plan task do not re-fire G0b — only the *first* action after `plan_approved` triggers it. |
| UNSOUND(#NN, drift, plan-task) | Action drifted from the plan's first task. The drift cite is mandatory: file path, planned vs observed, and the plan task that was violated. | **Halt next actions.** Surface drift to user with direct code+plan quotes, citing the violated `plan-task`. User options (the only three): (a) **revert** — `git restore <file>` to undo the action, then resume from plan-mode; (b) **override** — append `decision{kind=g0b_override, rationale=<text>}` and continue without the gate (audit trail preserved); (c) **return to plan-mode** — keep the action's filesystem effect, but force a fresh plan that incorporates the drift. |
| ABSTAIN | Critics had insufficient evidence (mixed votes, missing CITATION_PASS spot-checks, unreadable file state). | Re-dispatch `g-fidelity-critic` ×3 with the original prompt PLUS a `tool_input_digest` and the `plan-task` reference. After 2 ABSTAIN cycles in a row, halt and surface the same drift-options prompt as UNSOUND, with `<drift>` set to "abstain after 2 cycles". |
```

### 7. Failure-mode coverage

| Mode | Handling |
|---|---|
| G0b critic fan-out fails (subagent dispatch error) | Per `.claude/rules/agent-dispatch.md`: append `agent_dispatch_failure`; auto-retry once; on second failure, append `gate_verdict{gate=g0b, verdict=ABSTAIN, abstain_reason="dispatch_failure"}` and halt. |
| G6 critic fan-out fails (same) | Same pattern; append `gate_verdict{gate=g6, verdict=ABSTAIN, abstain_reason="dispatch_failure"}`; no candidates written; user can re-trigger by manually emitting `pending_dispatch`. |
| Journal corruption (YAML parse error in workflow-journal.yaml) | `get_journal_entries` already returns `[]` on parse error — both detection branches gracefully degrade to "no unpaired event found"; emit `[ivy-warn] journal-parse-failed`. |
| Race: two PostToolUse `run-gate.py --id g0b` invocations fire concurrently (parallel tool calls) | Per `journaling-contract.md` §4.2, the architecture assumes sequential writes — PostToolUse hooks fire in `hooks.json` order. `append_journal_event` is a non-locking read-modify-write; under the documented sequential-write assumption the second invocation observes the first's `gate_dispatched`, `predicate_g0b`'s pairing rule (per F-C3) finds T_d > T0 within the 2h staleness window → cycle in flight → returns False → emit_noop. No double-fire. If the sequential-write assumption is violated in the future (parallel-Agent fan-out writing the journal), both this gate and §4.2 require fcntl-locking before that change ships. |
| Race: cycle in flight (gate_dispatched written; gate_verdict not yet) and a second qualifying tool call arrives | Resolved by F-C3 pairing: `predicate_g0b` finds `gate_dispatched{gate=g0b}` at T_d > T0 with `(now - T_d) ≤ 2h` → returns False → no double-fire. Concrete: G0b critic vote takes ~90s; any tool calls during that window cleanly skip G0b until orchestrator writes `gate_verdict` (closing the cycle) or 2h passes (orphan recovery, see next row). |
| Orphan `gate_dispatched` (hook crashed or orchestrator never wrote `gate_verdict`) | Per F-C3 staleness fallback: if `(now - T_d) > 2h` and no later `gate_verdict{gate=g0b}` exists, `predicate_g0b` treats the dispatch as orphaned → returns True → re-fires G0b. Mirrors the existing 2h staleness convention in `is_workflow_stale` (`workflow_state.py`). G0b stays functional even when an individual cycle gets stuck. |
| Hook script crash mid-write | `append_journal_event` writes atomically via tempfile + rename; partial writes do not corrupt the journal. Test scenario: kill -9 the hook process during write; assert journal still parses. |
| Candidate dedup hash collision (two truly different candidates produce the same `candidate_id`) | sha256[:12] gives 48 bits of collision space; under 1e6 candidates per project lifetime, collision probability < 1e-2. Acceptable for dedup. If observed, lengthen the slice (`[:16]`) in a follow-up commit. |
| User-disabled IVY_DISPATCH_G6 forever | No data loss — candidates remain in the journal forever; the next session that re-enables the env-var picks them up via the candidate-extraction window (back to prior session_start). |
| Plan-mode active during PostToolUse `run-gate.py --id g0b` | **No explicit check** (per F-C2). Plan-mode is only signalled via system-reminder phrases (per `.claude/rules/plan-mode.md` § Detection signals) — invisible to a hook in shell space. The natural mechanism: in plan-mode no `plan_approved` event has been emitted yet (`plan_approved` is what *ends* plan-mode per `plan-mode.md` Step 4), so `predicate_g0b`'s "find most recent `plan_approved`" returns None → returns False → `emit_noop("PostToolUse", "g0b skipped: predicate returned False")` fires. No `gate_dispatched` written. Behaviour matches the prior design; the *explanation* corrects an unimplementable claim. |

### 8. End-to-end verification (4 scenarios)

The spec is "implemented" only when all four pass.

1. **G0b happy path.**
   - Setup: `plan_approved` event present in journal at ts=T0; matching plan file in `~/.claude/plans/`; first tool action is `Edit` on a file path the plan's first task names.
   - Action: invoke the Edit.
   - Invariants: within the same orchestrator turn, journal contains `gate_dispatched{gate=g0b, trigger="run-gate.py --id g0b", artifact=<file>, plan_approved_ts=T0}` (written by `dispatch_g0b` via the parametric runner), three `g-fidelity-critic` agent invocations recorded, and `gate_verdict{gate=g0b, verdict=SOUND}` (written by orchestrator after the critic vote, ts > T_d). A second qualifying tool call before the verdict lands MUST NOT trigger a second `gate_dispatched{gate=g0b}` (F-C3 pairing).

2. **G6 happy path.**
   - Setup: prior session contained at least one `progress{kind=fix_attempt}` event; `is_session_active()` was true; session ended cleanly (`session_end` written by `record/session-end.py`).
   - Action: start a new session with `IVY_DISPATCH_G6` unset (default = 1) and no fresh `pending_dispatch`.
   - Invariants: orchestrator's first turn writes `gate_dispatched{gate=g6}`, then `gate_verdict{gate=g6}`, then ≥1 `knowledge_captured` event with `candidate_id` matching the extracted candidate hash.

3. **Plan-mode skip.**
   - Setup: plan mode currently active; no `plan_approved` exists in the journal yet (per `plan-mode.md` Step 4, `plan_approved` is the event that *ends* plan-mode).
   - Action: invoke any `Edit` on the plan file (the only writable target under plan mode).
   - Invariants: PostToolUse `run-gate.py --id g0b` fires; `predicate_g0b` reads the journal, finds no `plan_approved`, returns False (no explicit plan-mode check needed per F-C2); `emit_noop("PostToolUse", "g0b skipped: predicate returned False")` fires; no `gate_dispatched{gate=g0b}` is appended.

4. **G0b UNSOUND halt + 3 recovery options (DR-14).**
   - Setup: `plan_approved` at ts=T0 references a plan whose first task says "edit `protocol-testing/bgp/bgp_speaker.ivy`"; user instead invokes `Edit` on `protocol-testing/quic/handshake.ivy`.
   - Action: invoke the (drifting) Edit.
   - Invariants: tool runs; PostToolUse `run-gate.py --id g0b` fires; `predicate_g0b` returns True (no prior `gate_dispatched{gate=g0b}` or `gate_verdict{gate=g0b}` with ts > T0); `dispatch_g0b` appends `gate_dispatched{gate=g0b, artifact="protocol-testing/quic/handshake.ivy", plan_approved_ts=T0}`; three critics return UNSOUND citing the file-path mismatch (planned `…/bgp_speaker.ivy` vs observed `…/handshake.ivy`); orchestrator writes `gate_verdict{gate=g0b, verdict=UNSOUND, drift=<str>, plan_task=<ref>}` and surfaces an AskUserQuestion listing exactly three options — revert, override, return-to-plan-mode — quoting both the planned and observed file paths from the verdict payload.
