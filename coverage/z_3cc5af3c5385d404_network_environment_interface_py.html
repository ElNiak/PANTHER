28 Network Environment Interface - Service Orchestration Framework 

29 

30 INetworkEnvironment extends IEnvironmentPlugin to provide network-isolated service orchestration

35 ## Architecture Role 

36 

37 Network environments serve as the foundation for PANTHER's protocol testing by providing: 

38 

39 1. **Service Lifecycle Management**: Coordinated startup, monitoring, and teardown of multiple services 

40 2. **Network Isolation**: Controlled network topologies for reproducible protocol testing 

41 3. **Template-Driven Configuration**: Jinja2-based configuration generation for dynamic service setup 

42 4. **Execution Environment Integration**: Seamless coordination with analysis tools (strace, Valgrind) 

43 5. **Event-Driven Monitoring**: Real-time environment state tracking and logging 

44 

45 ```mermaid 

46 graph TD 

47 A[Network Environment] --> B[Service Orchestration] 

48 A --> C[Network Topology] 

49 A --> D[Template Engine] 

50 A --> E[Execution Integration] 

51 

52 B --> F[Docker Compose] 

53 B --> G[Shadow NS] 

54 B --> H[Localhost Containers] 

55 

56 C --> I[Network Isolation] 

57 C --> J[Port Management] 

58 C --> K[Service Discovery] 

59 

60 D --> L[Jinja2 Templates] 

61 D --> M[Configuration Generation] 

62 D --> N[Variable Resolution] 

63 

64 E --> O[Analysis Tools] 

65 E --> P[Output Collection] 

66 E --> Q[Lifecycle Coordination] 

67 ```

69 ## Service Orchestration Pattern 

70 

71 Network environments implement a standardized service lifecycle: 

72 

73 1. **Generate Services**: Create service configurations from templates and test config 

74 2. **Prepare Environment**: Set up network topology and resource allocation 

75 3. **Launch Services**: Start services in dependency order with health monitoring 

76 4. **Deploy Services**: Execute service-specific deployment commands 

77 5. **Coordinate Execution**: Integrate execution environments for analysis

81 

82 The Jinja2 template engine enables dynamic configuration generation: 

83 

84 - **Service Templates**: Docker Compose files, Shadow configuration, startup scripts

93 - **Docker Compose**: Container-based isolation with Docker networks 

94 - **Shadow NS**: Network simulation with configurable topology and latency 

95 - **Localhost Single Container**: Simplified single-service testing environment

97 ## Execution Environment Coordination 

98 

99 Network environments seamlessly integrate with execution analysis tools: 

100 

101 - **Plugin Setup**: Automatic execution environment initialization 

102 - **Service Wrapping**: Process execution wrapped with analysis tools 

103 - **Output Coordination**: Centralized collection of network and execution outputs 

104 - **Lifecycle Synchronization**: Coordinated startup/teardown sequences

107 

108 Robust error handling ensures test reliability: 

109 

110 - **Service Failures**: Individual service failures don't crash entire environment

399 def resolve_environment_variables(self, env_vars: Dict[str, str]) -> Dict[str, str]: 

400 """Resolve environment variables with incremental substitution. 

401 

402 Processes a dictionary of environment variables, replacing ``${VAR}`` 

403 and ``$VAR`` references with previously resolved values so that 

404 variables can depend on one another. 

405 

406 Args: 

407 env_vars: Dictionary mapping variable names to values that may 

408 contain ``${VAR}`` or ``$VAR`` references to other variables 

409 in the same dictionary. 

410 

411 Returns: 

412 A new dictionary with all references resolved. 

413 """ 

414 import re 

415 

416 resolved: Dict[str, str] = {} 

417 for key, value in env_vars.items(): 

418 result = value 

419 # Replace ${VAR} patterns 

420 result = re.sub( 

421 r"\$\{([^}]+)\}", 

422 lambda m: resolved.get(m.group(1), m.group(0)), 

423 result, 

424 ) 

425 # Replace $VAR patterns (bare variable names) 

426 result = re.sub( 

427 r"\$([A-Z_][A-Z0-9_]*)", 

428 lambda m: resolved.get(m.group(1), m.group(0)), 

429 result, 

430 ) 

431 resolved[key] = result 

432 return resolved
